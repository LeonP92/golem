Package `internal/orchestrator/auth` provides two authentication mechanisms for the orchestrator: session cookie middleware and API key middleware. `CreateSession` generates a 32-byte random token, stores its SHA-256 hash in `db.Session` with a 7-day TTL, and sets an HTTP-only `Secure` `SameSite=Lax` cookie named `golem_session`. `RequireSession` reads that cookie on each request, hashes it, looks up the session (checking `expires_at > now`), loads the associated `db.User`, and stores it in the request context; unauthenticated requests are redirected to `/login`. `SessionUser(r)` extracts the `*db.User` from context. `RequireAPIKey` reads `Authorization: Bearer <key>`, iterates all `db.Shem` rows comparing with `bcrypt.CompareHashAndPassword`, and stores the matching `*db.Shem` in context; unmatched requests receive 401. `ShemFromRequest(r)` extracts the `*db.Shem` from context. No external auth libraries are used — only `crypto/rand`, `crypto/sha256`, `encoding/hex`, `net/http`, and `golang.org/x/crypto/bcrypt`.
